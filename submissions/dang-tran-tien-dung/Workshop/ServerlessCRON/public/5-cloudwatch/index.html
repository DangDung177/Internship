Monitoring with CloudWatch Logs

Overview

In this chapter, you will learn how to monitor your Lambda function executions using Amazon CloudWatch Logs and CloudWatch Metrics. These tools allow you to gain visibility into your scheduled CRON jobs and troubleshoot any failures or irregular behavior.

CloudWatch is automatically integrated with Lambda when you assign the AWSLambdaBasicExecutionRole permission.

Objectives

  • Explore logs generated by Lambda executions
  • Understand log streams and log events
  • View invocation metrics (count, duration, error rate)
  • Set up basic monitoring tools for production readiness

1. Access CloudWatch Logs

  1. Go to Amazon CloudWatch Console
  2. In the left menu, click Logs -> Log groups
  3. Search for your Lambda log group (e.g., /aws/lambda/ScheduledLoggerFunction)
  4. Click the Log group to view its streams
  5. Click the latest log stream to see detailed log entries

2. Understand Log Structure

Each Lambda invocation will produce a log stream containing:

  • START line (timestamp and request ID)
  • PRINT statements from your function (like “✅ Lambda function executed”)
  • END and REPORT lines showing duration, memory usage, and billing info

This log helps verify that:

  • The function triggered at the right time
  • Input and output are as expected
  • No errors or timeouts occurred

3. Review CloudWatch Metrics

  1. Navigate to the Metrics tab of your Lambda function
  2. Look for key indicators such as:
    • Invocations: how many times the function ran
    • Duration: average and maximum runtime
    • Errors: failed invocations
    • Throttles: if AWS had to limit your function
  3. You can customize the chart display and time range

✅ These metrics help you quickly detect problems like increased duration, missed schedules, or rising error rates.

4. Set Up Alarms (Optional)

You can set CloudWatch alarms to receive alerts when something goes wrong:

  • Go to CloudWatch -> Alarms -> Create Alarm
  • Choose the Lambda metric you want to monitor (e.g., Errors > 0)
  • In this example we will choose Errors.
  • Define a condition to alarm
  • Then We choose notification action. In this example, we will choose sending email via SNS.
    • Make sure to request confirmation of CloudWatchAlarms Topic. You can do it by go to Amazon SNS -> Subscriptions -> Request Confirmation -> Check for your Gmail(the mail might be in trash) -> Confirm Subscriptions

  • Here you can choose other actions like Lambda, Auto Scaling, EC2, Systems Manager and Investigation Acion
  • Name the alarm and click Next
  • Review every step and create alarm when you are done

This is a best practice for keeping your CRON jobs production ready and observable.

✅ Result

You’ve now learned how to:

  • Monitor scheduled Lambda executions with CloudWatch Logs
  • Read log output and troubleshoot issues
  • Use metrics to assess performance
  • Optionally configure alarms for proactive alerting
